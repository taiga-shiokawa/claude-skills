# drawio-shots：drawio へのスクリーンショット自動配置

既存の drawio ファイルの「フロー図の周りに画面スクリーンショットを並べ、該当ノードと点線でつなぐ」という手作業を自動化する。

設計方針：**判断が要らない処理はすべてスクリプトが決定的に行い、AI は「規約で決まらなかった対応付け」だけを考える。** これにより速く・安く・再現性のある結果になる。

## 全体フロー

```
1. inspect  → scripts/inspect_drawio.py で図とスクショを解析（自動マッチング込み）
2. resolve  → 未マッチ分だけ AI がノードラベルと突き合わせて対応付けを推測
3. confirm  → 対応付けの全体像をユーザーに提示して確認（省略条件あり）
4. place    → scripts/place_shots.py が配置を実行（バックアップ→埋め込み→保存）
5. report   → 何をどこに置いたか、確認方法を報告
```

### Step 1: inspect（解析）

```bash
python scripts/inspect_drawio.py <file.drawio> --shots <スクショのフォルダ>
```

JSON が返る。含まれるもの：

- `nodes`: 図中のノード一覧（id / ラベル / 絶対座標）
- `bbox`: 図全体のバウンディングボックス
- `shots`: スクショ一覧（ファイル名 / ピクセルサイズ）
- `auto_matches`: **規約で自動確定した対応付け**（method: number / substring）
- `ambiguous`: トークンは合致したが候補ノードが複数あるもの（candidates 付き）
- `unmatched`: 規約では対応が決まらなかったスクショ

ページが複数ある場合は `--page N` で指定（省略時は 0）。圧縮保存された drawio も自動で展開して読める。

### Step 2: resolve（AI フォールバック）

`auto_matches` はそのまま採用する。ここで悩み直さない — 規約マッチは決定的であることに価値がある。

`ambiguous` と `unmatched` についてだけ、ファイル名の意味とノードラベルを突き合わせて最も自然な対応を推測する。例：`メール画面.png` は「④ 提案メール下書き」のことだろう、という判断。どのノードにも対応しないスクショ（例：`IMG_2041.png`）は **アンカー無し**（`node_id` を省略）とし、図の右側の列に配置される。

### Step 3: confirm（確認）

対応付けの全体像を表で提示する：

| スクショ | 配置先ノード | 根拠 |
|---|---|---|
| ①テストパネル.png | ① 案件票の構造化 | 規約（丸数字） |
| メール画面.png | ④ 提案メール下書き | AI 推測 |
| IMG_2041.png | （アンカー無し・右側に配置） | 対応不明 |

**確認を挟む条件はひとつだけ**：AI 推測によるアンカー付けが1件以上あるとき（ユーザーが「確認不要」「おまかせ」等で事前に一任していれば省略可）。確認の目的は「推測を黙って混ぜない」ことなので、規約マッチと「対応不明→アンカー無し」だけで構成される場合は推測ゼロ＝確認不要で、そのまま実行してよい。ただしどのケースでも対応表は必ず提示する（実行前か報告時かの違いだけ）。

### Step 4: place（配置の実行）

確定した対応付けを mapping.json に書き、実行する：

```json
{
  "placements": [
    { "shot": "shots/①テストパネル.png", "node_id": "n1" },
    { "shot": "shots/メール画面.png", "node_id": "n4", "label": "提案メールの画面" },
    { "shot": "shots/IMG_2041.png" }
  ]
}
```

```bash
python scripts/place_shots.py <file.drawio> --mapping mapping.json
```

スクリプトが決定的に行うこと：

- 元ファイルを `<name>.drawio.bak-<timestamp>` にバックアップ
- 画像を base64 で埋め込み（PNG / JPEG 対応）、幅を `--max-width`（既定 480px）に縮小
- アンカーノードの位置に応じて図の**左右の外周列**に整列配置（アンカーの y に揃え、重なりは下へ送る）
- 画像から対応ノードへ**灰色の点線**を引く（`--no-edge` で省略可）
- 画像の下にキャプション（`label` 指定がなければファイル名）
- 保存して配置結果の JSON を出力

実行前に配置プランだけ見たい場合は `--dry-run`。出力先を変えたい場合は `--out <path>`（既定は上書き）。

### Step 5: report（報告）

配置結果の要約（何枚をどのノードに・バックアップの場所）を伝え、drawio で開いて位置を微調整できることを添える。

## 図の生成から頼まれた場合（一発実行の連結手順）

「構成図を作って、スクショも配置して」のような複合依頼では、次の順で連結する：

1. **drawio を通常どおり生成する**。このとき、スクショが対応し得る主要ノードのラベル先頭に **丸数字（①②③…）を振る**。この番号がファイル名規約との「契約」になり、スクショ側が番号どおりに命名されていれば対応付けは全件決定的（推測ゼロ・確認ゼロ）で完了する。タイトル・凡例・外部アクター（ユーザー等）など、画面が存在しない要素には振らない。
2. スクショが既にあれば、そのまま Step 1（inspect）以降の通常フローへ。
3. スクショがまだ無ければ、生成したノード一覧から **規約に沿ったファイル名の例**（`①案件票解析.png` など）を提示し、その名前で撮影・保存してもらってから配置に進む。

## ファイル名規約（ユーザー向け仕様）

| ファイル名の例 | マッチ方法 |
|---|---|
| `①テストパネル.png` / `1_パネル.png` / `02 検索.png` | **number**: 先頭の数字（丸数字・全角含む）が、ラベル先頭の数字と一致するノードへ |
| `候補検索.png` / `②候補検索_実行結果.png` | **substring**: `_`・`-`・空白で区切ったトークンがノードラベルに部分一致（`_` 以降の補足は無視される） |
| `IMG_2041.png` | どれにも合致しない → AI 推測 or アンカー無し配置 |

比較は NFKC 正規化（丸数字↔数字、全角↔半角を同一視）・大文字小文字無視・HTML タグ除去のうえで行われる。

## 注意点

- 対象は **既存の drawio ファイル**。図の新規作成はこのスキルの範囲外。
- 書き込みは必ずバックアップ後。失敗時はバックアップからの復元を案内する。
- 圧縮保存された drawio は読み込み時に展開し、保存は非圧縮 XML で行う（drawio はどちらも開ける）。
- 巨大なスクショも埋め込み時に幅 480px 相当へ縮小されるが、**元画像ファイル自体は変更しない**（縮小は表示サイズのみ。埋め込みデータは元画像のまま）。ファイルサイズが問題になる場合はユーザーに伝える。
- 同じスクショを二度配置しない：inspect の `existing_images` が多いときは、既に配置済みでないかユーザーに一言確認する。
