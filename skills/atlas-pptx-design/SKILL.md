# atlas-pptx-design — 図鑑掲載パワポのデザイン統一

GOOYAのAI活用図鑑（社内 AI 活用事例カタログ）に載せる PowerPoint を、図鑑サイトと同じ見た目に揃えるためのスキル。サイトの CSS デザイントークンをそのまま PowerPoint の配色・タイポグラフィ・部品に翻訳してある。デザイン仕様の詳細は `references/design-spec.md`、実装部品は `scripts/atlas_theme.py` にある。

## 設計思想

図鑑は「社内の AI 活用を横断的に眺め、事例を自分のタスクに応用できないか AI と相談しながら検討する」ためのサイト。掲載資料もその入口になるので、二つの原則を守る。

1. **見た目はサイトと地続きにする。** 読者が図鑑からパワポへ移動しても、同じ製品の中にいると感じられるように、色・角丸・バッジの意匠をサイトと一致させる。
2. **非エンジニアが読者。** 専門用語は「機能の説明 → 名前」の順で文中に説明を入れ、カタカナ語の連発と英語表記の裸出しを避ける。1スライド1メッセージ。

## 作業手順

### 0. 仕様と部品を読む

最初に `references/design-spec.md` を読む。配色・フォント・レイアウトレシピ・部品の使い方がすべてそこにある。仕様を読まずに手癖で配色すると、サイトと微妙に違う緑になって統一の意味がなくなる。

### 1. 内容を確定する

- **既存パワポの再デザイン**: python-pptx で全スライドの全テキストを段落単位で JSON に抽出する（抽出スクリプトの例は design-spec.md 末尾）。内容は原則変えず、デザインだけ差し替える。文言の手直しを頼まれた場合のみ書き換える。
- **新規作成**: ユーザーから素材をもらい、スライド構成案（1枚1メッセージの見出しリスト)を先に提示して合意してから作る。

日本語の文章を新しく書く・書き直すときは、必ず natural-japanese スキル（クイックで十分）を通す。既存文言をそのまま移すだけなら不要。

### 2. 生成スクリプトを書いて組み立てる

`scripts/atlas_theme.py` を import した Python スクリプトを作業用ディレクトリ（scratchpad）に書き、python-pptx で新しい .pptx を組み立てる。元ファイルは上書きせず、`元ファイル名_atlas.pptx` のような別名で出力する。

- 同じ構成のスライドが続く資料（事例集・手順集）は、抽出した JSON をループで流し込むテンプレート関数を1つ書く。スライドごとにコピペで組まない。
- テキスト量が枠に対して多いときは、フォントを1〜2pt落とすより先に「行を分ける・枠を広げる・スライドを分割する」を検討する。9pt 未満にはしない。

### 3. QA — 内容照合と視覚確認の両方を必ず行う

1. **内容照合**: 元と新の全テキストを比較し、脱落・重複がないことを確認する（再デザイン時）。
2. **視覚確認**: `scripts/render_slides.ps1 -Pptx <出力.pptx> -OutDir <画像出力先>` で全スライドを PNG に書き出し、**全枚数を実際に目で見る**。確認する順番は、はみ出し・見切れ → 重なり → 余白の偏り → コントラスト不足。PowerPoint 本体の COM を使うので、レンダリング結果は実際に開いたときと同じ。
3. 修正したら該当スライドを再レンダリングして再確認する。

### 4. 納品

出力ファイルをユーザーに渡し、変えた点（配色・フォント・レイアウト）と変えていない点（本文の内容）を短く報告する。図鑑への登録まで頼まれたら atlas-register スキルに引き継ぐ。

## やってはいけないこと

- スライド上部・側面を横断する色帯やアクセントストライプ（AI 生成資料の典型的な意匠。サイトにも存在しない）
- 緑の多用による「全部緑」化。緑は面積の 1〜2 割に抑え、白地と濃色テキストを主役にする
- 本文の中央揃え（中央揃えは表紙タイトルと数字バッジだけ）
- 元資料の文言の無断改変（デザイン統一の依頼は文言変更の許可ではない)
