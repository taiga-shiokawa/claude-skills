# daily-report — 開発日誌の記入と管理台帳の更新

その日の作業内容を、会話の文脈（今日のセッションでやったこと）から要約して
①Word の開発日誌に書き、②Excel の管理台帳に1日1行で記録する。

- 日誌フォルダ: `C:\Users\GOOYAラウンダー6\gooya.co.jp\MySharePoint - DailyReport`（引数でフォルダ指定があればそちら）
  SharePoint と同期しているフォルダ。パスに空白とハイフンを含むので、コマンドでは必ず引用符で囲む
  （PowerShell では `-LiteralPath`）。同期用の隠しファイル（`.` で始まる GUID 名）が混ざるので、
  フォルダ一覧を見るときは無視してよい。
- Word: `yyyymmdd_開発日誌.docx`（テンプレート: `開発日誌_テンプレート.docx`）
- Excel: `開発日誌_管理台帳.xlsx` シート「日誌一覧」

段落インデックス・台帳の列仕様・この環境特有の罠は
[references/template-map.md](references/template-map.md) に全部書いてある。
**書き込み前に必ず読むこと。**

## 鉄則

1. **docx/xlsx の読み書きは同梱の Node スクリプトだけで行う。** PowerShell の
   ZipFile で展開・再圧縮すると Word が開けないファイルができる（理由は reference 参照）。
2. **本人にしか分からない値は書かない。** 作業時間・時間帯・達成度・進捗率は
   常に空欄のまま残す（ユーザーの決定事項）。事実でない数字を残さないため。
3. **1日1行・1日1ファイル。** 既にあるものは更新し、増やさない。
4. **既存の内容を黙って消さない。** fill は空段落にしか書けない設計になっている。
   既存内容に足すときは append。台帳の更新も JSON に入れたキーの列しか書き換わらない。

## 手順

### 0. 事前チェック

```
skills_dir = このスキルのディレクトリ（scripts/ の親）
folder     = 日誌フォルダ
today      = 今日の日付（環境コンテキストの currentDate を使う。yyyymmdd と YYYY-MM-DD の両方）
docx       = folder\yyyymmdd_開発日誌.docx
```

- `folder` に `~$` で始まるファイルがあれば、対象の Word / Excel が開かれている。
  **開かれたまま書くと、あとで Word/Excel 側の保存に上書きされて消える。**
  先に閉じてもらうようユーザーに依頼して止まる（これはユーザー操作待ちが正しい）。
- 旧命名 `開発日誌_yyyymmdd.docx` が今日の日付で存在したら、正命名にリネームして続行。
- **書き込む前に、対象の docx と xlsx をスクラッチパッドへコピーしてバックアップする。**
  壊れたときに戻せる唯一の手段になる。

### 1. 内容の組み立て

今日のセッションでやったことを整理する。材料は会話の文脈が主。作業ディレクトリが
git リポジトリなら `git log --since=midnight --oneline` も裏取りに使える。

- **作業内容表（最大6行）**: 作業のまとまりごとに「作業内容／分類／進捗・成果」。
  成果は「何をして何が確認できたか」まで書く（作業名だけの行は後から読んで役に立たない）。
- **実装・変更内容**: 対象ファイルと変更点。なぜそうしたかの設計判断も1行添える。
- **問題・エラー表**: 実際に起きたものだけ。事象／原因／対応の3点セット。無ければ空のまま。
- **学び・気づき**: 次回以降も効く一般化された知見。その日限りの事実は書かない。
- **明日の予定・共有事項**: 未完のタスク、運用上の注意など。

### 2. Word への書き込み

**新規（今日のファイルがまだ無い）:**

```bash
# テンプレートをコピーしてから中身を確認
Copy-Item "folder\開発日誌_テンプレート.docx" "folder\yyyymmdd_開発日誌.docx"
node "skills_dir\scripts\read-docx.js" "docx"
```

reference の段落マップどおりに ops.json（`{"op":"fill","index":N,"lines":[...]}` の配列）を
スクラッチパッドに Write し、適用する:

```bash
node "skills_dir\scripts\fill-docx.js" "docx" "ops.json"
```

**更新（今日のファイルが既にある — 別プロジェクトのセッションが先に書いた等）:**

インデックスはテンプレートからズレているので、必ず `read-docx.js` で現状を見る。
空いているセクション・表の空行には `fill`、既に文があるセクションへの追記は
そのセクション末尾の段落への `append`。日付・案件名など既に正しく入っている値には触れない。

**書いたら読み戻して確認する:** `read-docx.js` をもう一度実行し、書いた内容が
意図した位置に入ったことを目視する。fill-docx.js が `"ok": true` を返しても
位置ズレは検出できない。確認するのは自分の目。

### 3. Excel 台帳への upsert

data.json をスクラッチパッドに Write して実行:

```json
{
  "date": "YYYY-MM-DD",
  "project": "プロジェクト／案件（Wordの基本情報と同じ文言）",
  "summary": "主な作業内容の要約（1〜2文。D列は一覧で読むものなので簡潔に）",
  "issues": "課題・懸念（無ければキーごと省略）",
  "tomorrow": "翌日の予定",
  "link": "Wordファイルのフルパス"
}
```

```bash
node "skills_dir\scripts\upsert-ledger.js" "folder\開発日誌_管理台帳.xlsx" "data.json"
node "skills_dir\scripts\read-ledger.js" "folder\開発日誌_管理台帳.xlsx"
```

- 出力の `mode` が update（既存行の更新）/ insert（空行へ）/ extend（表を1行延長）。
  同じ日に2回目を実行すると update になる — それが正しい挙動。
- 読み戻しで、対象日の行が**1行だけ**あり、B/H 列が数式のままであることを確認する。

### 4. 報告

- Word に書いたセクションと台帳の行番号・mode を報告する。
- 空欄のまま残した欄（作業時間・達成度・進捗率）を毎回明示的に伝える。
  ユーザーが自分で埋める前提の欄なので、伝え忘れると空欄のまま放置される。

## トラブル時

- スクリプトがエラーを返したら、同じ操作を PowerShell の ZIP 操作で代替**しない**こと。
  エラーメッセージを読み、ops.json / data.json の内容か対象ファイルの状態を疑う。
- 書き込み後に Word/Excel で開けない報告を受けたら、スクラッチパッドに残した
  実行前バックアップから復旧する（手順冒頭でコピーを取ること）。
