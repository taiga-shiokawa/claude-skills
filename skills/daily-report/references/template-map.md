### 既存ファイルを更新するとき

上のインデックスは**テンプレート時点**のもの。fill で段落が増えるとズレるので、
既存ファイルでは必ず `read-docx.js` を実行して現在のインデックスを見てから
ops.json を作る。ラベル段落（「日付」「本日の目標」等の固定文言）を目印にすると
迷わない。

- 空のセクションに書く → `fill`
- 既に文があるセクションに足す → そのセクション末尾の段落 index に `append`
- 既に書かれている値（日付・案件など）が正しければ触れない

## Excel 管理台帳の仕様

シート「日誌一覧」・テーブル NisshiLog（初期 ref A1:I21）。1日1行。

| 列 | 内容 | 扱い |
|---|---|---|
| A | 日付（シリアル値・書式 yyyy-mm-dd） | upsert-ledger.js が書く |
| B | 曜日 `=IF(A2="","",TEXT(A2,"aaa"))` | **数式。触れない** |
| C | プロジェクト／案件 | data.project |
| D | 主な作業内容（要約） | data.summary |
| E | 進捗率（0%〜100%） | **書かない**。既存値は保持される |
| F | 課題・懸念 | data.issues |
| G | 翌日の予定 | data.tomorrow |
| H | Wordファイル名 `=...TEXT(A2,"yyyymmdd")&"_開発日誌.docx"` | **数式。触れない** |
| I | 保存先リンク | data.link（Wordのフルパス） |

- 手入力セルは青字、黒字は自動計算（台帳「使い方」シートの色ルール）。
- upsert-ledger.js は日付一致→行更新 / A空行→そこへ / 満杯→1行延長を自動で行い、
  dimension・table ref・fullCalcOnLoad も面倒を見る。

## ファイル命名規則

台帳H列の数式が正: **`yyyymmdd_開発日誌.docx`**（日付が先）。
`開発日誌_yyyymmdd.docx`（日付が後）は旧命名。見つけたらリネームして正に揃える。

## この環境で過去に踏んだ罠（scripts/ が Node 製である理由）

- この環境に pandoc / python / LibreOffice は無い。あるのは Node と PowerShell 5.1。
- .NET の `ZipFile.CreateFromDirectory` はエントリ名をバックスラッシュで書き、
  ZIP 仕様違反で **Word が開けないファイル**を作る。
- PowerShell 5.1 は BOM 無し UTF-8 の .ps1 を ANSI として読み、日本語が文字化けする
  （param ブロックまで壊れて引数が全部空になる）。
- Excel の gid・行番号などで `0` は有効値。truthy 判定で弾くと先頭要素だけ壊れる。

この3つを全部回避するため、ZIP/XML 処理は scripts/ の Node スクリプトに固定した。
**docx/xlsx を PowerShell で展開・再圧縮しないこと。**
