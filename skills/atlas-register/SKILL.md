# AI活用図鑑への事例登録

チャットにアップロードされた資料を GOOYAのAI活用図鑑に掲載するまでを一気通貫で行う。
図鑑は「Drive = 資料の実体置き場、Sheets = 事例マスタ（何をどう表示するかの正）」という構成なので、
登録とは (1) Drive の正しい場所に正しい名前で資料を置き、(2) マスタに正しい形式で1行足すこと、の2つである。
どちらか片方だけでは図鑑に表示されない。

## 設定（環境の固定値）

| 項目 | 値 |
| --- | --- |
| ルートフォルダ「GOOYAのAI活用図鑑」 | `1TMsWuNK3KcKR1YyfGZkPh69ZYKQspQDT` |
| 事例マスタ Spreadsheet | `15O9X128y5f4FBZ40C-08FWbe4mtoXlQG7xB3dXA9Cl4` |
| マスタのシート名 | `cases` |
| 図鑑の URL（開発版） | `https://script.google.com/a/macros/gooya.co.jp/s/AKfycbwWV5tMLCAFjO7izMkkLawYPbSrKF5kkY_WpsTe7pKS/dev` |

図鑑を本番デプロイし直した場合や、マスタ・フォルダを移動した場合はこの表を更新すること
（folderId・Spreadsheet ID は Drive 内の移動では変わらない。変わるのは作り直した場合のみ）。
仕様の正は gooya-ai-atlas リポジトリの `docs/functional-design.md` §4 にあるが、
登録作業に必要な規則はすべて本スキルに書いてあるので、通常は読みに行かなくてよい。

## Drive の構造とファイル命名

```
GOOYAのAI活用図鑑/
├── 事例マスタ（Spreadsheet）
└── <カテゴリフォルダ>/          … 第一階層。Sheets の category 空欄時のフォールバック
    └── <事例フォルダ>/          … この folderId をマスタに記入する
        ├── main.<ext>           … 元資料。ext ∈ pptx|pdf|drawio|png|jpg|jpeg|webp
        └── preview.<ext>        … 任意。ext ∈ pdf|png|jpg|jpeg|webp（pptx・drawio は不可）
```

- ファイル名は **main / preview 以外は認識されない**。アップロードされた資料が `〇〇提案書.pptx` でも、格納時に `main.pptx` にする。
- **preview の効果**: main が PDF・画像なら preview なしでもサムネイルと Viewer が出る。
  main が pptx・drawio の場合は自動変換しない仕様のため、preview がないと種別アイコンと「Google Drive で開く」導線のみになる。
  `preview.pdf` なら Viewer で全ページ読める。表紙画像（png 等）なら1枚だけ表示される。
- 対応形式外（docx・xlsx 等）は登録できない。PDF に書き出してもらうよう案内する。

## 事例マスタの列仕様（A〜J の10列。1行 = 1事例。ヘッダは1行目）

| 列 | column | 規則 |
| --- | --- | --- |
| A | id | スラッグ（例: `copilot-20-tips`）。小文字英数とハイフンのみ。**既存 id と重複禁止**（重複すると後の行が黙って無視され、先の行が壊れていると事例ごと消える） |
| B | title | サイト表示タイトル。空なら Drive のフォルダ名で代替される |
| C | description | 事例概要。検索対象。空なら空表示 |
| D | category | カテゴリ名。**カテゴリフォルダ名と同じ文字列にする**（こちらが表示の正、フォルダ名は空欄時の予備） |
| E | tools | 使用ツール。**半角カンマ区切り**（全角「，」「、」では分割されない） |
| F | tags | タグ。同上 |
| G | published | **論理値の TRUE / FALSE**。TRUE のみ公開。文字列の "TRUE" は非公開扱いになる（下記の落とし穴参照） |
| H | featured | 論理値。TRUE で「おすすめ」バッジ付きで先頭に表示 |
| I | displayOrder | 数値。昇順。空なら最後尾（更新日の新しい順） |
| J | folderId | 事例フォルダの Drive ID |

## 手順

### 1. 資料とマスタの現状を確認する

- チャットにアップロードされたファイルのローカルパスと**サイズ**、拡張子を確認する。対応形式外なら PDF 書き出しを案内して止まる。
  サイズは手順4のアップロード経路の判断に使う。
- 資料が未添付で依頼された場合は、先に資料のアップロードを依頼する。
- Drive MCP の `read_file_content` で事例マスタを読む。ここから **既存カテゴリの一覧・既存 id の一覧・データ行数** を得る。
  これはヒアリングの選択肢・id 重複チェック・書き込み先の行番号の3つに使う。
- **登録済みの事例かどうかを必ず確認する。** マスタに同じ事例の行が既にあることがある
  （フォルダだけ先に作って資料が後から来る運用があるため）。その場合は新規行を足さず、
  空欄の列だけを埋める。id・folderId・category・published は既存の値を維持する。

### 1.5. 資料の内容をアップロード前にローカルで読む

Drive へ上げてから `read_file_content` で読むこともできるが、**先にローカルで読んでおくと、
起案の提示とアップロードの依頼を1往復にまとめられる**（ユーザーが資料を置いている間に内容確認ができる）。

pptx は zip なので、解凍して `<a:t>` タグを拾えば全スライドのテキストが取れる。
`scripts/extract_pptx_text.ps1` がこれを行う:

```powershell
powershell -File <skill>/scripts/extract_pptx_text.ps1 -Path "<pptx のパス>"
```

PDF の場合はローカル抽出が面倒なので、Drive へ上げてから `read_file_content` で読む方が早い。

### 2. ヒアリング（カテゴリ・公開・preview を1回でまとめて聞く）

AskUserQuestion で次を聞く。質問攻めにしないため、この1回にまとめる。

1. **カテゴリ**: 既存カテゴリを選択肢として並べ、「新しいカテゴリを作る」も含める。
   新規の場合はカテゴリ名を受け取る（フォルダ名とマスタの category に同じ文字列を使う）。
2. **公開**: すぐ公開する（TRUE）か、下書きとして登録する（FALSE）か。
   下書きの場合、公開は後で人がマスタの published を TRUE に切り替えるだけでよい旨を添える。
3. **preview**（main が pptx・drawio のときだけ）: この環境には PowerPoint が入っているので、
   **pptx なら preview.pdf は自分で作れる**（手順4を参照）。したがってユーザーに書き出しを頼むのではなく、
   「preview.pdf をこちらで用意して一緒に置きます」と伝えるだけでよい。
   drawio は変換手段がないので、表紙画像があれば任意で提供してもらう。

featured と displayOrder はここでは聞かず、手順5の確認時に既定値（FALSE・空欄）として提示し、変えたければそこで変えてもらう。
既存行の補完の場合は、カテゴリ・公開とも既存の値が確定しているのでヒアリング自体を省き、手順5の確認1回にまとめてよい。

### 3. フォルダを用意する

- 新規カテゴリなら、ルート直下にカテゴリフォルダを作る（`create_file`、mime `application/vnd.google-apps.folder`）。
  既存カテゴリなら `search_files`（`parentId = ルートID` + フォルダ mime）で該当フォルダを探す。
  マスタに category はあるのにフォルダが無い場合は作る。
- カテゴリフォルダの下に事例フォルダを作る。**フォルダ名は事例タイトルと同じにする**
  （title 空欄時のフォールバック元なので、揃えておくと運用が壊れにくい）。
- 同名の事例フォルダが既にある場合は、既存事例の更新なのか別事例なのかをユーザーに確認する。
  本スキルが扱うのは新規登録のみ。既存事例の資料差し替えは、その事例フォルダのファイルを入れ替えるだけでよい。

### 4. 資料を main.* として格納し、名前を検証する

**まず preview を用意する（main が pptx の場合）。**
この環境には PowerPoint があるので、`scripts/pptx_to_pdf.ps1` で `preview.pdf` を生成できる:

```powershell
powershell -File <skill>/scripts/pptx_to_pdf.ps1 -Path "<pptx のパス>" -Out "<出力先>\preview.pdf"
```

pptx は自動変換されない仕様のため、preview がないとサムネイルもビューアも出ない。
こちらで1コマンド作れるものを人に書き出させる理由はないので、黙って用意して一緒に置く。

**アップロード経路の選び方。**

- **A. 100KB 以下なら Drive MCP `create_file`**: base64 がツール呼び出しを通るのでコンテキストを食う。
  小さいファイルに限る。`title` を最初から `main.<ext>` にし、
  **必ず `disableConversionToGoogleType: true` を付ける**（付けないと pptx が Google スライドに変換され、
  拡張子の規約に一致せず事例が表示されない）。
- **B. それ以外はユーザーにドラッグ&ドロップを依頼**（実際の登録ではほぼこちらになる）。
  **Claude in Chrome の `file_upload` は使えない** — Drive の UI には操作可能な `input[type=file]` が無く、
  「新規」から開くのはネイティブのファイルピッカーなので触れない。試して時間を使わないこと。

  依頼するときは、**ローカルの1フォルダに `main.<ext>` / `preview.pdf` の名前で揃えて置いてから**、
  そのフォルダのパスと事例フォルダのリンクを渡す。名前を先に合わせておけば、
  ユーザーはドラッグするだけで済み、アップロード後のリネームも不要になる。元資料のあるフォルダの隣に
  `_図鑑アップロード用` のような作業フォルダを作るのが分かりやすい。

**格納後は必ず `search_files`（`parentId = 事例フォルダID`）で実際のファイル名を確認する。**
Drive はアップロード時に拡張子を落とすことがある（`main.pptx` を置いたつもりが `main` になっている。実際に起きた）。
名前が `main.<ext>` と完全一致していなければ `update_file` でリネームする。ユーザーの元ファイル名のままの場合も同様にリネームする。
このとき返ってくる**事例フォルダの ID を folderId として控える**。preview を預かった場合も同じ流れで `preview.<ext>` として格納・検証する。

### 5. 資料を解析してマスタの行を組み立て、ユーザーに確認する

- 格納済みの main ファイルを `read_file_content` で読み、内容から次を起案する:
  - **title**: 資料の表題を基に、一覧で内容が分かる簡潔な題（資料の表紙どおりでなくてよい）
  - **description**: 2〜3文。何の資料で、何が得られるか。検索対象なので固有名詞（ツール名・業務名）を含める
  - **tools**: 資料中で実際に使われている・言及されているツール名
  - **tags**: 検索でヒットさせたい語。業務領域・資料の種類（研修資料・テンプレート等）・キーワード
  - **id**: title の英訳から3〜4語のスラッグを作る。**手順1で得た既存 id と重複しないこと**
- 内容は資料から読み取れる事実だけで書く。資料にない効果や数字を盛らない。
- 組み立てた行（10列すべて。featured=FALSE・displayOrder=空欄の既定値込み）を表で提示し、
  修正がないか**1回だけ**確認を取る。ここが登録前の最終確認になる。

### 6. マスタに行を追加する（ブラウザ操作）

Sheets へ行を書き込む API は環境にないため、ブラウザで Spreadsheet を直接編集する。

- 書き込み先は `A<データ行数+2>` から（ヘッダが1行目のため。例: 既存2行なら A4）。
- **セル入力は必ず「名前ボックス方式」で行う**。セルをクリックして直接タイプすると、
  最初の数文字が編集モード遷移に食われて先頭が欠ける（実際に起きた）:
  1. 左上の名前ボックスをクリック → `ctrl+a` → セル参照（例 `A4`）をタイプ → Enter
  2. `F2` で編集モードに入る → `ctrl+a` → 値をタイプ → Enter
- published / featured は `TRUE` / `FALSE` とタイプすれば Sheets が論理値に自動変換する。
  入力後、セルの表示が**中央寄せ**になっていることを確認する（左寄せなら文字列になっており、非公開扱いになる）。
- **ヘッダ行（1行目）には絶対に触れない。** 誤って上書きした場合はその場で元の column 名に戻す。
- 全列入力後、スクリーンショットで行全体を確認する。

### 7. 図鑑で表示を検証する

- `図鑑のURL?id=<スラッグ>` を開く。
  - published = TRUE なら詳細画面が表示されるはず。タイトル・概要・ツール・タグ・種別・更新日を確認する。
  - published = FALSE なら「事例が見つかりません」になるのが**正しい**（非公開の直リンクは見えない仕様）。
    この場合は一覧に出ていないことだけ確認する。
- 反映されない場合の切り分け: マスタに行はあるか → published は論理値か（中央寄せか）→
  folderId は正しいか → 事例フォルダに `main.<ext>` が正しい名前であるか、の順で見る。
  現在キャッシュは無効化されているため反映は即時。将来キャッシュ（TTL 360秒）が入ると最大6分の遅延がありうる。

### 8. 完了報告

登録した行の内容・事例フォルダのリンク・図鑑の直リンクを報告する。あわせて:

- preview 未設置の pptx・drawio 事例には「preview.pdf を事例フォルダに置くだけでサムネイルが出る」ことを再案内
- 下書き登録の場合は「公開はマスタの published を TRUE にするだけ」と添える
- 図鑑は閲覧者本人の Drive 権限で表示が決まるため、共有ドライブのメンバー外には見えないことを必要に応じて注意

## 落とし穴（すべて実際に起きたこと）

- **拡張子落ち**: Drive アップロードでファイル名から拡張子が消えることがある。格納後の名前検証を省略しない。
- **published の文字列問題**: API・CSV 経由で文字列 `"TRUE"` を書くと図鑑は非公開と判定する。
  Sheets の UI でタイプする分には自動で論理値になる。判定はセルの寄せ（中央=論理値、左=文字列）で見る。
- **セル入力の先頭欠け**: 名前ボックス→F2 方式以外で入力しない。
- **Google 形式への自動変換**: MCP でのアップロード時に `disableConversionToGoogleType: true` を忘れると
  pptx が Google スライドになり、規約に一致しなくなる。
- **id 重複**: 重複行は黙ってスキップされる。エラーは出ないので、事前チェックだけが防御。
- **区切り文字**: tools / tags は半角カンマのみ。日本語入力のまま「、」で区切ると1つの長いタグになる。
- **Drive UI にファイル入力が無い**: `file_upload` は使えない（`input[type=file]` が DOM に無く、
  「新規」から出るのはネイティブのファイルピッカー）。100KB 超はドラッグ&ドロップ依頼が唯一の道。
- **登録済み事例の二重登録**: フォルダだけ先に作る運用があるため、マスタに行が既にあることがある。
  手順1で必ず確認し、あれば空欄補完に切り替える。

## この環境で PowerShell スクリプトを書くときの注意

同梱スクリプトを直す・増やすときに踏んだ問題。同じ形で書けば避けられる。

- **パイプラインを行末 `|` の継続行で書かない。** `$zip.Entries |` で改行して次行に `Where-Object` と
  書いた実装は、13件あるはずの結果が1件に化けた。`$matched = ... | Where-Object {...}` のように
  1行ずつ変数へ受けると正しく動く。
- **BOM 付き UTF-8 で保存する。** PowerShell 5.1 は BOM 無し UTF-8 を ANSI と解釈するため、
  日本語コメントを含むスクリプトが壊れうる。Write ツールで書いた後、
  `$body | Out-File -Encoding utf8` で書き直すのが確実。
- **`%TEMP%` への `Expand-Archive` を避ける。** このユーザー名には日本語が含まれ、
  展開が空振りして0件になった。zip は `System.IO.Compression.ZipFile` で直接読む。
- **外部 `powershell -File` の出力を `Select-Object -First N` で受けない。** 上流が打ち切られ、
  出力が途中で切れて誤った値に見えることがある（`SLIDE_COUNT: 13` が `1` に見えた）。
