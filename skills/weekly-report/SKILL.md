# 週次報告書作成（weekly-report）

エンジニアチームの週次報告書を、既存テンプレートの構成に沿って Google ドキュメントとして作成し、Google Drive の共有フォルダに保存する。

## 固定情報

| 項目 | 値 |
| --- | --- |
| テンプレート（Google ドキュメント） | ID: `1Qb_PtWG6VWb2z8wERfkNH6tK-wylfE-HY9bN1TiUJJg` |
| 格納先フォルダ「【エンジニアチーム】週次報告」 | ID: `1rhKReAoNnVNxzgd7HPC-ERSQhmA71sFA` |
| ファイル名規則 | `週次報告書_YYYYMMDD`（YYYYMMDD は**報告日**の日付。例: `週次報告書_20260813`） |

ID でのアクセスに失敗した場合（フォルダ改名・移動など）は、Google Drive MCP の `search_files` で `title contains '週次報告'` を検索して再特定する。それでも見つからなければユーザーに確認する。

Google Drive MCP ツールが未接続・未認証の場合は、作業を進めずにその旨をユーザーに伝える。

## 手順

### 1. ソースの受領

報告書の元ネタは**ユーザーが用意する Word ファイルまたは貼り付けテキスト**。会話にまだ提供されていなければ、次のように依頼していったん止まる（勝手に過去の報告書から捏造しない）:

> 今週の報告書のソースとなる Word ファイルをアップロードするか、内容をこのチャットに貼り付けてください。

- Word ファイル（.docx）が来たら、**docx スキル**（anthropic-skills:docx）で本文を抽出して読む。
- テキスト貼り付けならそのまま使う。

### 2. テンプレート構造の確認

Google Drive MCP の `read_file_content` でテンプレート（上記 ID）を読み、**最新の章立て・表構成**を把握する。テンプレートが読めない場合のフォールバックとして [references/template-structure.md](references/template-structure.md) に構成の写しがある。

構成は概ね次の4章 + 表紙情報:

1. 表紙: タイトル「週次報告書」/ 対象案件の一覧行 / 報告日・対象期間の表
2. `1. 全体サマリー` — 案件×（配信 / 状況 / 主な残作業）の一覧表
3. `2. 案件別の状況` — 案件ごとに **取り組み / 現状 / 課題** の3段落
4. `3. ご相談事項` / `4. 次やること` — 箇条書き

### 3. 原稿の作成

ソースの内容をテンプレート構成に**マッピング**して Markdown で原稿を作る。書き方のルール:

- **報告日**: ユーザー指定があればそれ、なければ今日の日付。曜日も付ける（例: 2026年8月13日（木））。
- **対象期間**: ソースに明記があればそれを使い、なければ前回報告の翌日〜報告日と推定して**ユーザーに確認**する。
- **案件の番号・名称**: 前回の報告書（格納先フォルダ内の直近ファイル）と整合させる。継続案件は同じ番号・名称を維持し、新規案件は末尾に追加する。
- **文体**: テンプレートの既存文と同じ「だ・である＋体言止め混在」の簡潔な報告文体。ソースが口語やメモ書きでも報告文体に整える。ただし**事実・数値はソースにあるものだけを使い、推測で補完しない**。
- ソースに「ご相談事項」「次やること」に相当する内容がなければ、その旨をユーザーに確認する（空のまま出さない）。

Markdown 記法の注意（Google ドキュメント変換で崩れないために）:

- 章見出しは `#`（1. 全体サマリー等）、案件見出しは `##` を使う。
- 表は標準的な Markdown テーブルで書く。ヘッダー行のセル内太字は `**...**` で表現する。
- 変換確認済みの要素: 見出し / 表 / 太字 / 箇条書き。これ以外の凝った記法（画像・チェックボックス等）は使わない。

### 4. ユーザー確認

作成した原稿（Markdown 全文）をユーザーに提示し、**OK をもらってからアップロードする**。共有フォルダへの投入は他メンバーの目に触れるため、無断で作成しない。修正指示があれば原稿を直してから次へ。

### 5. Google ドキュメントとして作成

Google Drive MCP の `create_file` を次のパラメータで呼ぶ:

- `parentId`: 格納先フォルダ ID
- `title`: `週次報告書_YYYYMMDD`
- `textContent`: 原稿の Markdown 全文
- `contentMimeType`: `text/markdown`

`text/markdown` を指定すると Drive 側で自動的に Google ドキュメントへ変換される（`disableConversionToGoogleType` は指定しない）。

作成後、レスポンスの `mimeType` が `application/vnd.google-apps.document` になっていることを確認し、`viewUrl` をユーザーに報告して完了。同名ファイルが既にある場合は上書きされず別ファイルになるため、作り直しの際は古い方を `trash_file` でゴミ箱へ移す（ユーザーに確認してから）。
